【一、这一讲学什么？】

徒弟啊，库（library）是软件开发里非常重要的概念。
简单说，就是把一堆编译好的代码打包起来，给别人用。

这一讲咱要搞清楚：

  1. 什么是静态库？什么是动态库？区别在哪？
  2. 怎么制作静态库（.a 文件）？
  3. 怎么制作动态库（.so 文件）？
  4. 怎么链接库？-L 和 -l 是啥意思？
  5. 动态库运行时找不到怎么办？LD_LIBRARY_PATH 是啥？
  6. 静态链接和动态链接生成的可执行文件有啥不一样？


【二、静态库 vs 动态库，大白话讲清楚】

想象你在做一道菜，需要用到"秘制酱料"。

【静态库 = 把酱料直接倒进菜里】
  - 菜做好了，酱料就在菜里了
  - 你端菜给别人，不用额外带酱料
  - 但菜会比较"多"（体积大）
  - 想换酱料？那得重做这道菜

【动态库 = 酱料单独放一个小碟子】
  - 菜里没有酱料，旁边放个小碟子
  - 你端菜给别人，得连碟子一起端
  - 菜本身比较"少"（体积小）
  - 想换酱料？换碟子就行，不用重做菜
  - 好几道菜可以共享同一碟酱料（省空间）

【对比总结】

  特性              静态库 (.a)        动态库 (.so)
  ─────────────────────────────────────────────────
  链接时机          编译时             运行时
  可执行文件大小    大（含库代码）     小（只有引用）
  运行时依赖        无（独立运行）     需要 .so 文件
  多程序共享        不能（各自一份）   可以（共享内存）
  库升级            重新编译程序       换 .so 就行
  启动速度          快（不用加载）     稍慢（要加载库）
  部署简单程度      简单（一个文件）   麻烦（要带库）
  适用场景          小库、不想折腾     大库、多程序共享


【三、制作静态库详细步骤】

就三步：

  1. 把源文件编译成 .o 目标文件
     g++ -c math_utils.cpp -o math_utils.o

  2. 用 ar 命令把 .o 打包成 .a
     ar rcs libmathutils.a math_utils.o

  3. 完成！libmathutils.a 就是静态库了

【ar 命令参数】
  ar rcs libxxx.a file1.o file2.o ...
     r - replace，库已存在就替换里面的成员
     c - create，创建库（静默模式，不输出提示）
     s - 建立索引，加快链接速度
         （不加 s 也可以，之后单独运行 ranlib libxxx.a 也行）

【查看静态库内容】
  ar t libmathutils.a        ← 看里面有哪些 .o 文件
  ar -x libmathutils.a       ← 把 .o 解压出来


【四、制作动态库详细步骤】

也是三步，但多了两个关键选项：

  1. 编译 .o 时加 -fPIC
     g++ -c -fPIC math_utils.cpp -o math_utils.o

  2. 链接时加 -shared
     g++ -shared -o libmathutils.so math_utils.o

  3. 完成！libmathutils.so 就是动态库了

【-fPIC 是什么？】
  Position Independent Code，位置无关代码。

  为啥动态库需要这个？
  因为动态库在运行时才加载，加载到内存的哪个位置
  是不确定的。如果代码里用了绝对地址，加载到不同
  位置就会出错。

  -fPIC 生成的代码全部用相对地址，加载到任何位置
  都能正常运行。

  静态库为啥不需要？
  因为静态库的代码在编译时就整个复制到可执行文件里了，
  地址是固定的。

【查看动态库信息】
  file libmathutils.so      ← 看文件类型
  ldd libmathutils.so       ← 看它依赖哪些其他库
  nm -D libmathutils.so     ← 看导出了哪些符号（函数/变量）


【五、链接库的方法】

链接库用 -l（小写的 L）参数：

  g++ main.o -lmathutils -o app

编译器会自动去找 libmathutils.a 或 libmathutils.so。
（这就是为啥库名要以 lib 开头的原因！）

【库搜索路径 -L】

如果库不在系统默认路径（/lib, /usr/lib），
就要用 -L 告诉编译器去哪找：

  g++ main.o -L. -lmathutils -o app
                ↑
                当前目录

-L 和 -l 是一对好搭档：
  -L 指定搜索目录（去哪里找）
  -l 指定库名字（找哪个）

【链接顺序很重要！】

如果库 A 依赖库 B，那 A 要写在 B 前面：

  g++ main.o -lA -lB -o app   ✓ 正确
  g++ main.o -lB -lA -o app   ✗ 可能报错

为啥？因为链接器是从左往右找，遇到未定义的符号
才去后面的库里找。写反了可能找不到。

【静态链接 vs 动态链接】

默认情况下，同一个目录里既有 .a 又有 .so，
编译器会优先选动态库。

如果想强制静态链接：
  g++ main.o -static -lmathutils -o app
  （或者直接写 .a 文件路径也行）


【六、动态库的运行时问题（重点！）】

徒弟，这是新手最容易踩的坑，师傅给你讲清楚。

【现象】
  编译好好的，一运行就报错：
  error while loading shared libraries: libxxx.so:
  cannot open shared object file: No such file or directory

【原因】
  -L 是给编译器（编译时）用的，告诉编译器去哪找库。
  但程序运行的时候，操作系统的动态链接器（ld.so）
  不知道你的库在哪。
  编译器没把库的路径告诉可执行文件。

【三种解决方法】

方法一：设置 LD_LIBRARY_PATH 环境变量（临时用，开发调试）
  export LD_LIBRARY_PATH=/path/to/libs:$LD_LIBRARY_PATH
  ./app

  特点：简单，不用改程序。但只对当前终端有效。
  适合开发调试的时候用。

方法二：安装到系统目录（正式发布）
  sudo cp libxxx.so /usr/local/lib/
  sudo ldconfig
  ./app

  特点：一劳永逸，所有程序都能用。
  但需要 root 权限，适合安装第三方库。

方法三：编译时加 -rpath（推荐，开发/测试用）
  g++ main.o -L. -lxxx -Wl,-rpath,. -o app

  什么意思？
    -Wl,xxx  把 xxx 传给链接器 ld
    -rpath   运行时库搜索路径

  就是把库的路径"写进"可执行文件里，
  运行的时候直接去那找。

  特点：不用设环境变量，不用装系统目录。
  但路径是写死的，移动了库的位置就不行了。

【咱们这个例子用的是方法三】
  Makefile 里写了 -Wl,-rpath,.
  意思是把当前目录加到运行时搜索路径里。


【七、动手试试】

咱这个示例项目里有两个库：
  libmathutils    数学计算库
  libstringutils  字符串处理库

还有一个主程序 main.cpp，会用到这两个库。

试试下面这些命令，感受一下：

  1. 编译静态库版本
     make static
     ./app_static
     ls -lh app_static    ← 看看多大

  2. 编译动态库版本
     make shared
     ./app_shared
     ls -lh app_shared    ← 跟静态版比比大小

  3. 查看库文件信息
     make info

  4. 看看动态库依赖
     ldd app_shared
     ldd app_static

  5. 试试去掉 -Wl,-rpath,. 会怎样
     （修改 Makefile，去掉那行，重新编译运行）

  6. 试试用 LD_LIBRARY_PATH
     （去掉 rpath 之后，试试：LD_LIBRARY_PATH=. ./app_shared）

【老师傅建议】
  多动手试！光看不练假把式。
  改改 Makefile，故意搞出点错误，看看报错信息是什么样的。
  踩过坑、填过坑，知识才是你的。


【八、老师傅的经验之谈】

1. 【默认用静态还是动态？】
   小项目、简单库 → 静态库，简单省事，不用管运行时依赖
   大项目、多程序共享 → 动态库，省空间、好升级
   第三方库 → 一般都是动态库（Qt, Boost 等）

2. 【库的命名】
   一定要 lib 开头！-lxxx 才能找到。
   Windows 下是 .dll，但也有类似的命名约定。

3. 【动态库版本号】
   正式发布的动态库一般带版本号：
     libfoo.so.1.2.3    完整版本
     libfoo.so.1        主版本号（兼容的）
     libfoo.so          软链接，指向最新版
   这是个约定，保证二进制兼容性。
   新手先不用管这么细，知道有这回事就行。

4. 【符号可见性】
   默认情况下，动态库会导出所有函数和全局变量。
   但其实很多内部函数不需要导出。
   可以用 -fvisibility=hidden 把默认设为隐藏，
   然后用 __attribute__((visibility("default")))
   标记需要导出的函数。
   这样库更小，加载更快，也更安全。
   （进阶话题，以后再研究）

5. 【静态链接的坑】
   如果多个动态库都静态链接了同一个静态库，
   那内存里会有多份代码，浪费空间。
   而且如果静态库有全局变量，每个库各有一份，
   可能出问题。这个要注意。

6. 【不要怕库】
   很多新手一提到库就发怵，觉得很复杂。
   其实本质很简单：库就是一堆编译好的 .o 打包起来，
   链接的时候把需要的拿过来用。
   理解了这个本质，什么库都不怕。
