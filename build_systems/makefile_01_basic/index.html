示例 1：Makefile 入门 —— 老师傅的第一课

徒弟啊，欢迎来到 Makefile 的世界。这第一节课，咱不求多，只求把最基本的概念吃透。根基不牢，地动山摇。

一、这节课学什么？

  1. 什么是 Makefile？

    —— 自动编译的"说明书"。你告诉它怎么编译，它帮你干活。

  2. 一条规则的三要素：

    目标 : 依赖
	命令
    • 目标（target）：你想要什么
    • 依赖（prerequisite）：用什么来做
    • 命令（recipe）：怎么做

  3. make 命令怎么工作？

    • 它在当前目录找 Makefile 文件
    • 默认执行第一条规则
    • 通过比较文件的修改时间，决定要不要重新编译

二、怎么用这个示例？

打开终端（命令行），进入这个目录，然后试试：

  1. 第一次编译

    $ make

    你会看到输出（Linux/macOS）：

    g++ -o main main.cpp

    Windows 上会多一个 .exe：

    g++ -o main.exe main.cpp

    然后目录下多了一个 main 可执行文件（Windows 上是 main.exe）

  2. 运行程序

    $ ./main            (Linux/Mac)
$ main.exe          (Windows)

    你会看到：Hello, Makefile!

  3. 再敲一次 make

    $ make

    你会看到：

    make: 'main' is up to date.

    （Windows 上是 make: 'main.exe' is up to date.）

    意思是：main 已经是最新的了，不用重新编译。 ——这就是 make 的聪明之处！

  4. 修改一下 main.cpp（比如改改打印的文字），再 make

    $ make

    哎，它又重新编译了！因为源码比目标新。

  5. 清理生成的文件

    $ make clean

    可执行文件被删掉了，目录又干净了。

三、老师傅的经验之谈

坑 1：TAB 还是空格？

命令行前面必须是 TAB 键，不能是空格！ 这个坑不知道坑了多少新手。报错信息通常是：

"missing separator.  Stop."

看到这个错误，先检查是不是用了空格代替 TAB。

坑 2：Makefile 的文件名

默认 make 找的是 Makefile（首字母大写）、makefile（全小写）、GNUmakefile（GNU make 专用）。推荐用 Makefile，首字母大写，这样在文件列表里排在前面，好找。 如果你文件名不是这个，就得用 make -f 你的文件名 来指定。

坑 3：第一条规则是默认目标

make 不带参数时，执行的是 Makefile 里的第一条规则。 所以通常把最终要生成的东西放在最前面。

为什么要用 Makefile？

徒弟你可能会想：不就一个文件嘛，我直接敲 g++ 不就行了？ 说得对，一个文件确实没必要。但等你项目大了：

  • 十几个源文件，每个都要单独编译
  • 还要链接各种库
  • 编译选项一大堆
  • 改了一个文件，不想全部重编

这时候 Makefile 的威力就出来了。咱一步一步来，先把最简单的搞明白，后面才有底气玩复杂的。

四、课后小练习

  1. 试试修改 main.cpp，观察 make 什么时候重新编译，什么时候不编译。
  2. 试试把命令前的 TAB 改成空格，看看会报什么错（然后改回来哈）。
  3. 试试在 clean 前面加一条别的规则，看看 make 默认执行哪条。
