# 示例 2：变量与伪目标 —— 老师傅的第二课

徒弟，上一节课咱学了最基础的规则，一个目标一条命令。这节课啊，咱要把 Makefile 写得"像样儿"了。工欲善其事，必先利其器。变量和伪目标，就是咱的利器。

## 一、这节课学什么？

1. 变量的定义和使用

   - 为什么要用变量？（DRY 原则：Don't Repeat Yourself）
   - 常用变量命名惯例（`CC`, `CXX`, `CFLAGS`, `OBJS`, `TARGET`...）
   - 怎么定义变量，怎么引用变量（`$(变量名)`）

2. 自动变量

   - `$@`  目标名
   - `$^`  所有依赖
   - `$<`  第一个依赖

   这三个是最常用的，必须背下来！

3. 伪目标 `.PHONY`

   - 什么是伪目标
   - 为什么需要伪目标（避免和同名文件冲突）
   - 常用的伪目标：`all`, `clean`, `install`, `run`

4. 多文件编译

   - 先把每个 `.cpp` 编译成 `.o`（目标文件）
   - 再把所有 `.o` 链接成可执行文件
   - 这样改了一个文件，只需要重编对应的 `.o`

## 二、怎么用这个示例？

进入 `makefile_02_variables` 目录，然后试试：

1. 编译

   ```bash
   $ make
   ```

   或者

   ```bash
   $ make all
   ```

   你会看到：

   ```text
   g++ -Wall -g -std=c++11 -c main.cpp -o main.o
   g++ -Wall -g -std=c++11 -c utils.cpp -o utils.o
   g++ -Wall -g -std=c++11 -o app main.o utils.o
   ========== 编译完成！==========
   ```

   （Windows 上最后一条是 `-o app.exe`；运行用 `./app.exe`）

2. 运行

   ```bash
   $ make run
   ```

   它会先检查要不要重新编译，然后直接运行程序

3. 清理

   ```bash
   $ make clean
   ```

   所有 `.o` 文件和可执行文件都删掉了

4. 试试增量编译

   ```bash
   $ make          # 先编译一次
   # 改一下 utils.cpp
   $ make          # 再编译
   ```

   你会发现：只重新编译了 `utils.o`，然后重新链接
   `main.o` 没变，就不重编了——这就是 `make` 的核心价值！

## 三、老师傅的经验之谈

### 经验 1：变量名用大写，这是行业惯例

就像 C 语言里的宏定义用大写一样，`Makefile` 里的变量也习惯大写。不是必须的，但大家都这么写，你写小写别人看着别扭。

### 经验 2：常用变量名别乱改

`CC`、`CFLAGS`、`LDFLAGS` 这些名字，是有"约定俗成"的含义的。你把编译器变量叫 `MY_COMPILER` 也行，但别人读你的 `Makefile` 就得愣一下。用标准名字，大家都省心。

### 经验 3：`.PHONY` 一定要加

新手最容易忘的就是 `.PHONY`。忘了会怎么样？平时可能没事，哪天目录下冒出来个叫 `clean` 的文件，你 `make clean` 就不好使了，而且你还不知道为啥。记住：不生成文件的目标，一律 `.PHONY` 伺候。

### 经验 4：@ 符号的妙用

命令前面加 `@`，`make` 就不会把命令本身打印出来。适合用在 `echo` 这种"输出提示信息"的命令上。不加 `@` 的话，先打印一遍 `echo "xxx"`，再输出 `xxx`，啰嗦。

### 坑 1：变量引用要加 `$()`

- 定义变量直接写：`VAR = value`
- 引用变量必须写：`$(VAR)` 或者 `${VAR}`

忘了加括号，写成 `$VAR`，`make` 会把 `$V` 当成变量名，然后剩下的 `AR` 原样输出——结果就错了！

### 坑 2：`=` 和 `:=` 的区别

这个咱先提一嘴，后面再细讲。

- `=` 是"延迟展开"——用到的时候才展开
- `:=` 是"立即展开"——定义的时候就展开

新手先用 `=` 就行，等你遇到问题了再研究 `:=`

## 四、头文件依赖的问题（提前预告）

徒弟你细心的话可能发现了：咱手动写了 `main.o` 依赖 `utils.h`。那如果 `utils.h` 又 `include` 了别的头文件呢？项目大了，头文件依赖关系错综复杂，手动写根本不现实。

别担心，后面的示例咱会学"自动生成依赖"的高级技巧。饭一口一口吃，路一步一步走。

## 五、课后小练习

1. 把 `CXX` 改成 `clang++`，看看能不能用 clang 编译。
   （装了 clang 的话可以试试，没装就算了）

2. 在 `CXXFLAGS` 里加个 `-O2`（优化选项），再编译看看。

3. 试试故意不加 `.PHONY`，然后 `touch` 一个叫 `clean` 的文件，看看 `make clean` 会怎么样。（试完记得删掉 `clean` 文件哈）

4. 加一个新的 `.cpp` 文件（比如 `debug.cpp`），手动修改 `Makefile` 让它也参与编译。
   ——你会发现每个 `.o` 都要写一条规则，好麻烦！
   别急，下节课咱就学"模式规则"，一下就解决了。

好，这节课就到这儿。变量和伪目标是 `Makefile` 的基本功，务必练熟了再往下走。
