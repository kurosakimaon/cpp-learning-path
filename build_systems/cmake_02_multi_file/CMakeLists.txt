# ============================================================
#  CMake 示例 02 - 多文件项目
#  老师傅注释版，每行都给你讲明白
# ============================================================

# 老规矩，先规定最低版本
cmake_minimum_required(VERSION 3.10)

# 项目名称
project(MultiFileDemo)

# ============================================================
#  方法一：老老实实把所有源文件列出来（推荐！）
# ============================================================
#
# add_executable(demo main.cpp utils.cpp math.cpp)
#
# 徒弟你看，跟第一个例子比，就是 add_executable 后面
# 多列了几个源文件而已。就这么简单。
#
# 这种写法的好处：
#   1. 清清楚楚，哪个文件参与编译一目了然
#   2. 新增/删除文件时，手动改一下 CMakeLists.txt 就行
#   3. CMake 能准确知道哪些文件变了，增量编译没问题
#
# 但是呢，文件多了写起来麻烦，所以有人就想用 file(GLOB)
# 自动找文件。咱下面就讲讲这个。

# ============================================================
#  set 命令：定义变量
# ============================================================
#
# set 是 CMake 里最常用的命令之一，用来给变量赋值。
# 格式：set(变量名  值1 值2 值3 ...)
#
# 这里我们把所有源文件的路径存到 SOURCES 这个变量里，
# 后面用 ${SOURCES} 就能引用它了。
#
# 为什么要用变量？
#   1. 代码更整洁，源文件列表单独放一块
#   2. 万一后面有好几个地方要用到这个列表，改一处就行
#
set(SOURCES
    main.cpp
    utils.cpp
    math.cpp
)

# 顺便定义一下头文件目录（虽然这个例子里头文件就在当前目录，
# 但咱先演示一下 include_directories 的用法）
set(INCLUDE_DIRS
    ${CMAKE_CURRENT_SOURCE_DIR}
)
# 解释一下 CMAKE_CURRENT_SOURCE_DIR：
# 这是 CMake 内置变量，表示当前正在处理的 CMakeLists.txt 所在的目录。
# 是个绝对路径，比如 /home/xxx/project/cmake_02_multi_file
# CMake 内置了好多这样的变量，后面慢慢接触。


# ============================================================
#  include_directories：添加头文件搜索路径
# ============================================================
#
# 徒弟你想想，你写 #include "utils.h" 的时候，
# 编译器怎么知道去哪儿找这个 utils.h？
#
# 答案是：编译器会在一些默认目录里找，
# 如果你把文件放在别的目录，就得告诉编译器一声。
#
# include_directories 就是干这个的。
# 它会把你给的路径加到编译器的头文件搜索列表里。
#
# 【老师傅警告】
# include_directories 是"全局"的！
# 加了之后，这个 CMakeLists.txt 以及它下面所有子目录里的
# 目标（可执行文件、库）都会加上这些头文件路径。
# 小项目无所谓，大项目里容易造成"头文件污染"。
# 更好的做法是 target_include_directories（后面示例会讲）。
#
include_directories(${INCLUDE_DIRS})


# ============================================================
#  用变量来创建可执行文件
# ============================================================
#
# ${SOURCES} 就是引用上面定义的 SOURCES 变量。
# CMake 里引用变量的语法就是 ${变量名}，跟 shell 里的 $变量名 类似。
#
add_executable(demo ${SOURCES})


# ============================================================
#  补充知识：file(GLOB) 的用法及注意事项
# ============================================================
#
# 有人嫌一个个列源文件太麻烦，就想用 file(GLOB) 自动收集：
#
#   file(GLOB SOURCES "*.cpp")
#
# 这条命令会把当前目录下所有 .cpp 文件都找出来，放到 SOURCES 变量里。
# 看起来挺方便是吧？
#
# 【老师傅严重警告】
#  file(GLOB) 这玩意儿，新手最爱用，但坑也最多！
#
#  最大的坑：CMake 不会自动检测新增的文件！
#
#  怎么说呢？你用 file(GLOB) 收集了所有 .cpp 文件，
#  CMake 配置的时候（就是 cmake .. 那一步）把文件列表算出来了。
#  但是后来你又加了一个新的 .cpp 文件，这时候 CMake 不知道啊！
#  你直接 make 的话，新文件不会被编译，链接时报错。
#  你必须手动重新运行 cmake .. 才行。
#
#  更坑的是：你忘了重新 cmake，找半天 bug 找不到，
#  最后发现是新文件没编进去。这种事儿老师傅我见多了。
#
#  还有个坑：你临时放了个 test.cpp 在目录里，
#  本不想编进去的，结果 GLOB 一把全给你收了。
#
#  【结论】
#  正式项目里，老老实实把源文件一个个列出来。
#  不要贪省事用 file(GLOB)！
#  当然，如果你只是写个小 demo 自己玩玩，随便用。
#
#  （ps：CMake 3.12 以后出了个 CONFIGURE_DEPENDS 参数，
#   能一定程度上缓解这个问题，但也不是完美的。
#   有兴趣自己去查，咱先把基础打牢。）

#  老师傅的话：
#  多文件项目其实没什么神秘的，就是 add_executable 后面
#  多写几个源文件而已。关键要理解：
#
#  1. 头文件和源文件是分开的，编译时只编源文件(.cpp)
#  2. include_directories 告诉编译器去哪儿找头文件
#  3. 用 set 定义变量可以让 CMakeLists.txt 更整洁
