示例 3：模式规则与函数 —— 老师傅的第三课

徒弟，上节课咱学会了用变量和伪目标，Makefile 像那么回事了。但你有没有发现一个问题：每个 .o 文件都得手动写一条规则，文件多了，那玩意儿写起来累死人啊！

这节课啊，咱就学几招"自动化"的功夫，让 Makefile 自己干活。

一、这节课学什么？

  1. wildcard 函数 —— 自动发现源文件

    不用手动列文件了，make 自己找。

  2. patsubst 函数 —— 批量替换文件名

    .cpp 列表一键转 .o 列表。

  3. 模式规则 %.o: %.cpp —— 一条规则搞定所有 .o

    这是 Makefile 里最强大的特性之一，必须掌握！

  4. foreach / filter 函数 —— 遍历和过滤

    处理文件列表的瑞士军刀。

  5. ifeq 条件判断 —— 让 Makefile 会"思考"

    调试版和发布版切换，就是靠这个。

  6. include 包含其他 Makefile —— 模块化

    把配置抽出去，主 Makefile 更干净。

二、怎么用这个示例？

进入 makefile_03_patterns 目录，然后试试：

  1. 基本编译

    $ make

    你会看到它自动编译了所有 .cpp 文件。

  2. 运行

    $ make run

  3. 查看 Makefile 信息（强烈建议试试！）

    $ make info

    你可以看到：

    • 编译器是什么
    • 编译选项有哪些
    • 自动发现了哪些源文件
    • 当前是调试模式还是发布模式

    这招用来调试 Makefile 特别好使，变量的值一目了然。

  4. 发布模式编译

    $ make clean
$ make BUILD=release

    用 make BUILD=release info 看看 CXXFLAGS 有啥不一样。 （release 模式有 -O2 优化，debug 模式有 -O0 和 -DDEBUG）

  5. 试试 foreach 和 filter

    $ make test
$ make test2

    看看输出，感受一下函数的威力。

  6. 加一个新文件试试（重点！）

    新建一个 extra.cpp，随便写点东西（比如定义一个函数） 不用改 Makefile，直接 make 看看它会不会自动编译 extra.cpp？ ——这就是 wildcard + 模式规则的魅力！

三、老师傅的经验之谈

经验 1：wildcard + patsubst + 模式规则 = 黄金组合

这三个玩意儿搭配着用，90% 的编译场景都能搞定。记不住别的没关系，这仨必须刻在脑子里。

经验 2：模式规则里的依赖要小心

咱示例里写的是 %.o: %.cpp $(HDRS) 意思是所有 .o 都依赖所有头文件。 小项目无所谓，大项目就有问题了——改一个头文件全部重编。 正确的做法是"自动依赖生成"，用编译器的 -MMD 选项生成 .d 文件。 别着急，下节课咱就讲这个。

经验 3：善用 info 目标调试 Makefile

写 Makefile 跟写代码一样，也会出 bug。变量的值对不对？函数展开后是啥样？整个 info 目标，把关键变量都打印出来，调试起来方便得很。

经验 4：include 的文件如果不存在

默认 include 的文件不存在，make 会报错退出。想让它"没有就算了"，用 -include（前面加个减号）。后面讲自动依赖的时候会用到这个技巧。

坑 1：通配符和 wildcard 的区别

新手常问：我直接写 SRCS = *.cpp 不行吗？ 不行！Makefile 里变量赋值时，*.cpp 就是字面量"*.cpp"，不会展开成实际的文件名。 只有在规则的目标/依赖里，或者在 wildcard 函数里，通配符才会展开。 记住：要展开通配符，用 wildcard 函数！

坑 2：模式规则的 % 匹配

模式规则里的 %，在目标和依赖里是同一个值。目标匹配到什么，依赖里的 % 就是什么。这是一一对应的关系，别搞混了。

坑 3：ifeq 的缩进

ifeq 不能加 TAB 缩进！它是 Makefile 的语法，不是命令。必须顶格写，就像定义规则一样。加了 TAB make 会把它当成命令的一部分，那就乱套了。

四、课后小练习

  1. 新建一个 extra.cpp 和 extra.h，在 main.cpp 里调用它。不用改 Makefile，看看 make 能不能自动编译。

  2. 用 make BUILD=release 编译，然后用 make BUILD=release info 看看 CXXFLAGS 有什么变化。

  3. 在 config.mk 里改一下 TARGET 的名字，重新 make，看看生成的可执行文件名变了没有。 ——这就是 include 的好处，配置和逻辑分离。

  4. （挑战题）试试用 addprefix 函数，给所有 .o 文件名前面加上 obj/ 前缀。比如 main.o 变成 obj/main.o。 （提示一下，下节课要用到这个技巧哦）

好，这节课就到这儿。模式规则和函数是 Makefile 进阶的关键，掌握了它们，你就算是入门了。下节课咱要玩个大的——完整的项目结构！
