【一、项目介绍】

徒弟啊，欢迎来到综合实战项目！

前面你学了很多知识点：OOP、STL、文件I/O、
智能指针、设计模式、错误处理……
但你可能会问：这些东西怎么串起来用？
真实项目里代码是怎么组织的？

这个项目就是为了解答这些问题而设计的。

我们要做一个命令行的 Todo（待办事项）工具，
功能不算复杂，但麻雀虽小，五脏俱全。
通过这个项目，你能看到：
  - 一个完整的 C++ 项目长什么样
  - 代码怎么分层、怎么组织
  - 设计模式怎么在实际项目中应用
  - 各个知识点怎么串联起来使用

做完这个项目，你对 C++ 编程的理解会更上一层楼。


【二、功能清单】

这个 Todo 工具支持以下功能：

  1. 添加任务
     - 指定标题、优先级（高/中/低）
     - 指定截止日期、标签
  2. 删除任务
     - 按 ID 删除
  3. 列出所有任务
     - 支持按 ID / 优先级 / 截止日期排序
     - 支持按标签筛选
     - 支持只显示未完成的
  4. 标记完成
     - 切换完成/未完成状态
  5. 数据持久化
     - 自动保存到文件
     - 启动时自动加载
  6. 帮助信息
  7. 退出程序

命令示例：
  add 写作业 -p high -d 2024-12-31 -t 学习,重要
  list -sort priority -pending
  complete 1
  delete 2
  help
  exit


【三、架构设计思路】

为什么代码要分层？为什么不能全写在 main 里？

师傅告诉你，小项目怎么写都行，但项目一大，
代码全堆在一起就是灾难。改一个地方，
可能影响十个地方，bug 满天飞。

所以我们要"分而治之"，把代码按职责分开。
我们的项目分了四层：

  ┌─────────────────────────────────────┐
  │           ConsoleUI                 │  ← 界面层
  │     （和用户交互，显示和输入）        │
  ├─────────────────────────────────────┤
  │      Command / CommandFactory       │  ← 命令层
  │     （封装操作，解析输入）           │
  ├─────────────────────────────────────┤
  │         TaskList / Task             │  ← 业务层
  │     （核心业务逻辑，数据模型）       │
  ├─────────────────────────────────────┤
  │        Storage / FileStorage        │  ← 持久化层
  │     （数据存储，文件读写）           │
  └─────────────────────────────────────┘

每层的职责：

  1. 【界面层（ConsoleUI）】
     - 只负责和用户打交道
     - 显示信息、读取输入
     - 不包含任何业务逻辑
     - 好处：以后想换 GUI，这层换掉就行

  2. 【命令层（Command）】
     - 把"操作"封装成命令对象
     - 每个命令负责一件事
     - 工厂负责解析输入、创建命令
     - 好处：新增操作只要加新命令类，不用改老代码

  3. 【业务层（TaskList / Task）】
     - 核心业务逻辑都在这里
     - 管理任务、增删改查、排序筛选
     - 不关心数据存在哪、界面怎么显示
     - 好处：业务逻辑集中，好测试、好维护

  4. 【持久化层（Storage）】
     - 只负责数据的保存和加载
     - 用抽象接口，具体实现可以换
     - 好处：以后换数据库、换云端，这层换掉就行

这种分层设计，就是所谓的"关注点分离"（Separation of Concerns）。
每一层只关心自己的事，层与层之间通过接口通信。
这样代码结构清晰，修改起来不容易出问题。


【四、设计模式在项目中的应用】

这个项目用到了好几种设计模式，
师傅给你逐个拆解：

1. 【命令模式（Command Pattern）】
   位置：Command.h / Command.cpp
   作用：把"请求"封装成对象

   每个操作（添加、删除、列出...）都是一个 Command 子类，
   都有 execute() 方法。这样做的好处：
   - 可以把命令排队、记录日志
   - 可以实现撤销/重做（本项目没做，但可以扩展）
   - 调用者和执行者解耦

   在我们的项目里，命令模式最大的价值是：
   把"解析输入"和"执行操作"彻底分开了。
   ConsoleUI 只负责把用户输入交给工厂，
   工厂创建命令对象，然后执行。
   UI 完全不知道有哪些具体命令。

2. 【工厂模式（Factory Pattern）】
   位置：CommandFactory.h / CommandFactory.cpp
   作用：封装对象创建逻辑

   CommandFactory 负责根据用户输入创建对应的命令对象。
   调用者（ConsoleUI）不用知道有哪些具体命令类，
   只要调用 parse() 就能得到命令对象。

   好处：
   - 新增命令只要在工厂里加一个 case
   - 创建逻辑集中，方便维护
   - 调用者和具体类解耦

3. 【策略模式（Strategy Pattern）】
   位置：TaskList.h / TaskList.cpp 中的排序和筛选
   作用：把算法（策略）封装成可互换的对象

   排序有多种方式（按ID、按优先级、按日期），
   筛选也有多种方式（按状态、按标签、按优先级）。

   我们用 std::function 把"怎么比"、"怎么筛选"
   封装成可调用对象，调用时传不同的策略就行。

   好处：
   - 新增排序/筛选方式，不用改 sorted()/filtered() 方法
   - 算法可以灵活组合
   - 符合开闭原则（对扩展开放，对修改关闭）

4. 【RAII（资源获取即初始化）】
   位置：FileStorage 中使用 ofstream/ifstream
   作用：自动管理资源

   C++ 的 fstream 本身就是 RAII 的典范：
   构造时打开文件，析构时自动关闭。
   你不用手动调用 close()，也不用担心异常时忘记关闭。

   另外，我们用 unique_ptr 管理 Command 对象，
   也是 RAII 的应用——智能指针自动释放内存。

5. 【面向接口编程】
   位置：Storage 抽象基类
   作用：依赖抽象，不依赖具体实现

   Storage 是一个抽象基类（接口），
   FileStorage 是它的具体实现。
   上层代码（Command、ConsoleUI）只依赖 Storage 接口，
   不依赖 FileStorage 具体类。

   好处：
   - 以后换存储方式（数据库、云端），上层不用改
   - 方便测试（可以写个 MockStorage）
   - 符合依赖倒置原则


【五、每个文件的作用】

项目文件清单，逐个给你讲：

  ├── CMakeLists.txt        ← CMake 构建配置
  │                            告诉编译器怎么编译这个项目
  │
  ├── include/              ← 头文件（声明）
  │   ├── Task.h            ← 任务类（数据模型）
  │   │                        定义 Task 的属性和方法
  │   │
  │   ├── TaskList.h        ← 任务列表（核心业务逻辑）
  │   │                        管理所有任务，增删改查、排序筛选
  │   │
  │   ├── Storage.h         ← 持久化接口（抽象基类）
  │   │                        定义 save/load 接口
  │   │
  │   ├── FileStorage.h     ← 文件存储实现
  │   │                        Storage 接口的文件实现
  │   │
  │   ├── Command.h         ← 命令接口 + 各具体命令
  │   │                        命令模式：每个操作一个类
  │   │
  │   ├── CommandFactory.h  ← 命令工厂
  │   │                        解析用户输入，创建命令对象
  │   │
  │   ├── ConsoleUI.h       ← 控制台用户界面
  │   │                        显示、输入、主循环
  │   │
  │   └── Utils.h           ← 工具函数
  │                            通用辅助函数（字符串处理等）
  │
  ├── src/                  ← 源文件（实现）
  │   ├── Task.cpp          ← Task 类的实现
  │   ├── TaskList.cpp      ← TaskList 类的实现
  │   ├── FileStorage.cpp   ← FileStorage 类的实现
  │   ├── Command.cpp       ← 所有命令类的实现
  │   ├── CommandFactory.cpp← 命令工厂的实现
  │   ├── ConsoleUI.cpp     ← 控制台 UI 的实现
  │   ├── Utils.cpp         ← 工具函数的实现
  │   └── main.cpp          ← 程序入口
  │
  └── tests/                ← 单元测试
      └── test_task.cpp     ← Task 和 TaskList 的测试
                               用 assert 实现，无第三方依赖


【六、怎么编译运行】

这个项目用 CMake 构建，跨平台。

方法一：用 CMake（推荐）

  # 1. 创建构建目录
  mkdir build
  cd build

  # 2. 生成构建文件
  cmake ..

  # 3. 编译
  # Linux/macOS:
  make
  # Windows (Visual Studio):
  cmake --build . --config Release
  # Windows (MinGW):
  mingw32-make

  # 4. 运行
  # Linux/macOS:
  ./bin/todo_cli
  # Windows:
  bin\Release\todo_cli.exe

方法二：直接用 g++（简单粗暴）

  # 直接编译所有源文件
  g++ -std=c++17 -I include src/*.cpp -o todo_cli

  # 运行
  ./todo_cli

方法三：运行测试

  # 编译测试
  g++ -std=c++17 -I include tests/test_task.cpp src/Task.cpp src/TaskList.cpp -o test_task

  # 运行测试
  ./test_task


【七、怎么扩展（练习题）】

学编程最好的方法就是动手改。
这里给你留了一些扩展练习，
从简单到困难，试着做做看：

【入门级】
  1. 给任务加一个"备注"字段，支持添加和显示备注。
  2. 给 list 命令加一个 -all 选项，显示已完成和未完成的（默认只显示未完成？）。
  3. 让 add 命令支持用中文优先级（高/中/低）。

【进阶级】
  4. 实现"编辑任务"功能：edit <ID> -title "新标题" -p high
  5. 实现"清空已完成任务"的命令：clear-completed
  6. 给任务列表加"批量操作"：比如批量删除、批量打标签。
  7. 优化数据加载：让加载后任务 ID 保持不变（而不是重新分配）。
     （提示：给 TaskList 加一个 importTasks 方法）

【高级级】
  8. 实现命令的撤销/重做功能（Undo/Redo）。
     （提示：每个 Command 加一个 undo() 方法，用栈保存历史）
  9. 把存储格式改成 JSON（需要引入 nlohmann/json 库）。
  10. 加一个"统计"命令，显示完成率、按标签统计等。
  11. 把 ConsoleUI 换成 Qt 图形界面（学了 Qt 之后再做）。

【挑战级】
  12. 实现多用户支持，每个用户有自己的任务列表。
  13. 加上网络功能，实现多设备同步（这个就很大了）。


【八、学习建议】

1. 【先跑起来，再读代码】
   先编译运行一下，感受一下这个工具怎么用。
   用用 add、list、complete 这些命令，
   对功能有个整体认识。

2. 【从数据模型开始读】
   读代码的顺序建议：
   Task.h → Task.cpp → TaskList.h → TaskList.cpp
   → Storage.h → FileStorage.h → FileStorage.cpp
   → Command.h → Command.cpp → CommandFactory.h → CommandFactory.cpp
   → ConsoleUI.h → ConsoleUI.cpp → main.cpp

   从数据开始，再到业务逻辑，再到上层应用，
   这样读起来最顺。

3. 【关注设计，而不是细节】
   读这个项目，重点不是看某一行代码怎么写，
   而是理解：
   - 为什么要分这么多类？
   - 类和类之间是什么关系？
   - 这样设计有什么好处？
   - 如果是我，我会怎么设计？

4. 【亲手改一改】
   光看不练假把式。
   照着上面的扩展练习，自己动手改改。
   改坏了没关系，大不了重新来。
   改代码的过程中，你对架构的理解会更深。

5. 【对照设计模式学习】
   读的时候想想：
   - 这里用了什么设计模式？
   - 为什么要用这个模式？
   - 不用的话会怎么样？
   - 还能用在什么地方？


【九、老师傅的话】

徒弟啊，做项目比看 10 个 demo 都管用。

师傅当年学 C++ 的时候，也看过很多书、很多教程，
感觉自己什么都懂了。但真到写项目的时候，
才发现：怎么把这些东西串起来？代码怎么组织？
文件怎么分？类怎么设计？

这些问题，看书是学不会的，必须亲手做项目。

这个项目虽然小，但五脏俱全。
你把它吃透了，再看其他 C++ 项目，
思路就清晰多了。

师傅跟你说几句真心话：

1. 【不要怕代码多】
   刚看到十几个文件，你可能会慌：
   "这么多，我看得懂吗？"
   别怕，一个一个来。
   每个文件都不大，职责都很单一。
   把每个类都搞懂了，整个项目就懂了。

2. 【设计比编码重要】
   写代码只占 20% 的时间，
   剩下 80% 的时间都在想：怎么设计？
   设计好了，写代码就是水到渠成的事。
   设计不好，写着写着就乱了，到处都是补丁。

3. 【分层是基本功】
   不管什么项目，分层都是最基本的架构思想。
   UI 归 UI，业务归业务，数据归数据。
   分清楚了，代码就清爽了。

4. 【设计模式是工具，不是目的】
   不要为了用设计模式而用设计模式。
   每个模式都有它适用的场景。
   用对了，代码更清晰；
   用错了，反而更复杂。

5. 【多写项目，多看优秀代码】
   编程是手艺活，熟能生巧。
   多写项目，多看别人的好代码，
   你的水平自然就上去了。

最后送你一句话：
「纸上得来终觉浅，绝知此事要躬行。」
看再多教程，不如亲手写一个项目。
去动手吧，徒弟！
