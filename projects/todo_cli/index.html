📖 项目简介

这是一个完整的命令行待办事项（Todo）管理工具。麻雀虽小，五脏俱全—— 它涵盖了面向对象编程、STL 容器与算法、文件 I/O、智能指针、 设计模式、错误处理等多个核心知识点。

通过这个项目，你将学会如何把零散的知识点串成一个完整的应用， 理解真实项目中的代码分层、架构设计和设计模式应用。 做项目比看 10 个 demo 都管用！

🏗️ 架构设计

项目采用经典的四层架构，每层职责清晰：

界面层（ConsoleUI）
负责显示和用户交互
命令层（Command + Factory）
封装操作、解析输入
业务层（TaskList + Task）
核心业务逻辑、数据模型
持久化层（Storage + FileStorage）
数据存取、文件 I/O

分层原则：上层依赖下层，每层只关心自己的职责。 层与层之间通过接口通信，修改一层不影响其他层。

💡 学习建议

  • 先跑起来，再读代码：先编译运行，对功能有整体认识，再深入代码细节。
  • 从数据模型开始读：Task → TaskList → Storage → Command → ConsoleUI，从底向上读最顺。
  • 关注设计，不只是语法：重点理解"为什么这么分层"、"为什么用这个模式"，而不是某行代码怎么写。
  • 亲手改一改：照着 tutorial.md 里的扩展练习，自己动手加功能。改代码比读代码学的多。
  • 对照设计模式学习：思考每个模式的适用场景，不用死记硬背，理解了自然就会用。

👴 老师傅的话

做项目比看 10 个 demo 都管用。纸上得来终觉浅，绝知此事要躬行。

徒弟啊，这个项目虽然不大，但它是你从"会写代码"到"会做项目"的第一步。

师傅当年学编程的时候，也走过弯路——看了很多书，学了很多语法，觉得自己什么都懂了。但真要写个东西的时候，发现根本不知道从哪下手。文件怎么分？类怎么设计？代码怎么组织？

这些东西，看书学不会，必须亲手做。

这个项目，师傅建议你这么学：

  • 第一遍：跑起来，用一用。 感受一下功能，知道它能干啥。
  • 第二遍：读代码，理解架构。 跟着 tutorial.md 的指导，把每个文件都读懂。重点理解设计思想。
  • 第三遍：动手改，加功能。 选几个扩展练习自己做。改坏了没关系，重来就是。改代码的过程中，你才会真正理解为什么要这么设计。

最后师傅说一句：编程是手艺活，熟能生巧。 你写的代码越多，踩的坑越多，进步就越快。别害怕犯错，每个 bug 都是成长的机会。
