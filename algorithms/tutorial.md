# 算法与数据结构

> 基本功中的基本功，面试必考、工作常用

## 一、模块简介

徒弟啊，算法和数据结构，说是程序员的基本功，一点都不夸张。不管你做前端、后端、还是客户端，算法和数据结构都是绕不开的。

为什么重要？

第一，面试必考。大厂小厂都考，不考的很少。

第二，工作常用。你选什么容器、怎么优化性能，底层全是算法和数据结构。

第三，锻炼思维。学算法不是为了背代码，是为了训练你分析问题、解决问题的能力。

这个模块有两个源码文件 + 两个可视化页面，带你把排序算法和常用数据结构过一遍。

## 二、学习目标

学完本模块，你要能做到：

1. 理解常见排序算法的思路和复杂度
2. 知道每种排序的优缺点和适用场景
3. 理解常见数据结构的原理和操作
4. 能根据场景选择合适的数据结构
5. 学会用可视化的方式理解算法过程

## 三、文件列表与学习重点

## 四、学习顺序建议

师傅给你个学习方法，亲测有效：

### 先看可视化，建立直觉

别上来就啃代码。先打开可视化页面，点一点，看一看，感受一下。

排序可视化：

- 选不同的算法，看它们怎么把数组排好的
- 调一下速度，慢下来看细节
- 感受一下：哪个快？哪个慢？为什么？

数据结构可视化：

- 看看链表是怎么插入删除的
- 看看树是怎么遍历的
- 看看哈希表是怎么插入和查找的

有了直观感受，再看代码就好懂多了。

### 再读源码，理解实现

看完可视化，再去读对应的源码文件。对照着可视化的动画，一行行读代码，理解每一步在干嘛。

排序那块，建议按这个顺序学：冒泡 → 选择 → 插入 → 归并 → 快速 → 堆排序

数据结构那块，建议按这个顺序学：数组 → 链表 → 栈/队列 → 树 → 哈希表

### 最后自己写一遍

看懂了不代表你会了。关掉源码，自己动手写一遍，写不出来再回去看。能独立写出来，才算真正掌握了。

别嫌麻烦，这个过程是必须的。

## 五、核心知识点梳理

咱把最核心的东西拎出来：

### 1. 排序算法怎么选

| 算法 | 平均时间 | 最坏时间 | 空间 | 稳定 |
| --- | --- | --- | --- | --- |
| 冒泡排序 | O(n²) | O(n²) | O(1) | 是 |
| 选择排序 | O(n²) | O(n²) | O(1) | 否 |
| 插入排序 | O(n²) | O(n²) | O(1) | 是 |
| 归并排序 | O(nlogn) | O(nlogn) | O(n) | 是 |
| 快速排序 | O(nlogn) | O(n²) | O(logn)平均/O(n)最坏 | 否 |
| 堆排序 | O(nlogn) | O(nlogn) | O(1) | 否 |
| 计数排序 | O(n+k) | O(n+k) | O(n+k) | 是 |

怎么选：

- 数据量小、基本有序 → 插入排序（常数因子小）
- 需要稳定排序 → 归并排序 / `std::stable_sort`
- 一般情况 → 快速排序（平均性能好，工程中用 introsort）
- 怕最坏情况 → 堆排序（保证 O(nlogn)）
- 范围很小的整数 → 计数排序（O(n+k)，非比较排序）

实际工作中，直接用 STL 的 `sort` 就行，人家优化得比你写的好多了。但原理你得懂。

### 2. 数据结构怎么选

- 数组：连续内存，随机访问 O(1)，中间插入删除 O(n)
- 链表：离散内存，随机访问 O(n)；已知插入位置的插入/删除 O(1)，但找位置仍是 O(n)
- 栈：后进先出（LIFO），`push/pop` 都是 O(1)
- 队列：先进先出（FIFO），`push/pop` 都是 O(1)
- 二叉搜索树：查找/插入/删除平均 O(logn)，最坏 O(n)
- 平衡二叉树（红黑树）：查找/插入/删除都是 O(logn)
- 哈希表：查找/插入/删除平均 O(1)，最坏 O(n)

怎么选：

- 需要随机访问 → 数组（`vector`）
- 频繁中间插入删除 → 链表（但实际用得少）
- 要有序、查找快 → 平衡树（`map/set`）
- 只要查找快、不需要有序 → 哈希表（`unordered_map`）

### 3. 为什么要有这么多数据结构

一句话：trade-off（权衡）。没有一种数据结构是万能的。有的快但占空间，有的省空间但慢，有的查找快但插入慢，有的插入快但查找慢。

你要根据实际场景，选择最合适的。这就是数据结构的精髓。

### 4. 时间复杂度的本质

时间复杂度不是算具体多少秒，是看数据量增大时，运行时间增长的趋势。

- O(1) → 数据再怎么涨，时间不变
- O(logn) → 数据翻一倍，时间只增加一点点
- O(n) → 数据翻一倍，时间也翻一倍
- O(n²) → 数据翻一倍，时间翻四倍

写代码之前先想想：这个方案时间复杂度是多少？数据量大了会不会崩？

## 六、常见坑与注意事项

### 1. 背代码不理解思想

很多人学算法就是背代码，背完就忘，换个问法就不会了。

别背代码，要理解思想。快速排序的核心思想是"分治 + 分区"，归并排序的核心思想是"分治 + 合并"，哈希表的核心思想是"哈希函数 + 数组"。

理解了思想，代码自然就能写出来。

### 2. 忽略边界条件

算法题最容易错的就是边界。空数组怎么办？只有一个元素怎么办？指针越界了吗？递归终止条件对吗？

写完算法，一定要测边界情况。

### 3. 上来就想最优解

遇到算法题，别急着想最优解。先想暴力解法，再优化。暴力解法至少是对的，最优解想半天想不出来更亏。

### 4. 只刷题不总结

刷了几百道题，换个新题还是不会。为什么？因为没总结。

做完一道题，要想想：

- 这道题用了什么思想？
- 类似的题还有哪些？
- 有什么通用的套路？

刷题不在多，在精。做一道，会一类。

## 七、老师傅的经验之谈

### 1. 算法和数据结构是基本功，别偷懒

徒弟，师傅跟你说句实在话：算法和数据结构，你迟早要补的。现在偷的懒，以后面试的时候要还的。

而且这东西不是为了面试，工作中真的有用。你选容器、优化性能、设计系统，哪个离得开算法和数据结构？

早点学，早受益。

### 2. 可视化是个好东西

算法这东西，光看文字描述太抽象了。看动画就直观多了。排序是怎么排的、树是怎么转的、哈希表是怎么冲突的，看一遍动画比看十遍文字都强。

咱这个模块的可视化页面，建议你多玩一玩。

### 3. 不要怕难，也不要急

算法对新手来说确实不简单，一开始看不懂很正常。别着急，慢慢来。

今天看不懂的，明天再看一遍；这周写不出来的，下周再试试。学算法就是个螺旋上升的过程。坚持下去，总有一天会开窍的。

### 4. 思维比代码重要

学算法，最重要的不是你能写出多少行代码，而是你能不能想到正确的思路。思路对了，代码只是时间问题。思路错了，写再多代码也白搭。

所以做题的时候，先想思路，思路想清楚了再动手写代码。

### 5. 工作中别自己造轮子

最后说一句实际的：工作中写代码，排序就用 `std::sort`，哈希表就用 `unordered_map`，别自己写排序、自己写哈希表。你写的大概率没标准库的好，还容易出 bug。

那为什么还要学原理？因为理解了原理，你才知道什么时候用、怎么用，出了问题也知道怎么回事。知其然，更要知其所以然。
