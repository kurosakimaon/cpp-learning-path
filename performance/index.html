📖 模块简介

性能优化是 C++ 程序员的核心竞争力之一。同样的功能，有人写出来快如闪电， 有人写出来慢如蜗牛。差距在哪里？在于对硬件的理解、对语言的掌握、以及对性能的敏感度。

本模块从 CPU 缓存原理讲起，带你理解为什么同样的逻辑、不同的写法， 性能能差好几倍。然后盘点 6 个最常见的性能陷阱， 每个都有正反对比和实测数据。学完本模块，你写出来的代码天然就会更快。

🏗️ CPU 内存层级

理解性能的第一步，是理解数据是怎么流动的。现代 CPU 的内存是分层的，速度越快的容量越小：

寄存器
几个字节
~0.3ns
L1 缓存
32KB / 核
~1ns
L2 缓存
256KB / 核
~4ns
L3 缓存
8-64MB 共享
~15ns
内存
几十 GB
~100ns

核心洞察：CPU 访问内存比访问 L1 缓存慢约 100 倍！ 写出缓存友好的代码，性能可能提升数倍甚至数十倍。

💡 学习建议

  • 每个实验都亲手跑一遍：光看没用，自己跑一遍，亲眼看到性能差距，印象才深刻。建议用 Release 模式编译（-O2）。
  • 先理解缓存，再谈优化：缓存是很多计算密集型程序性能优化的基石。理解了缓存，你就能自己推导出很多优化方法，不用死记硬背。
  • 养成"性能意识"：写代码的时候，脑子里多根弦——这个地方会不会慢？有没有不必要的拷贝？内存访问模式友好吗？
  • 先测量，再优化：永远不要猜瓶颈在哪里。用性能分析工具找到热点，集中火力优化 20% 的代码，获得 80% 的收益。
  • 别钻微观优化的牛角尖：对内置类型来说，i++ 和 ++i、位运算代替乘除法……这些编译器通常都会处理掉；但自定义迭代器的 i++ 可能多构造一个临时对象，所以养成写 ++i 的习惯也没坏处。把精力放在宏观的架构和数据结构上。

👴 老师傅的话

性能优化不是奇技淫巧，是科学。先测量，再优化，别猜，用数据说话。

徒弟啊，很多人学性能优化，一上来就学各种"黑科技"。什么手动汇编啊、位运算技巧啊……但师傅告诉你，那些都是末节。

真正的性能优化，90% 的收益来自于正确的架构、正确的数据结构、缓存友好的代码。把这些做好了，代码自然就快了。

师傅给你讲个真实的故事：

  • 刚入行的时候，师傅也以为性能优化就是抠细节。把一个循环里的 i++ 改成 ++i，沾沾自喜觉得优化了。后来才知道，编译器早就帮你做了。
  • 真正开窍是在，师傅把一个项目里的链表全改成了 vector，速度直接快了 5 倍。什么都没改，就换了个数据结构。那一刻我才明白：数据结构才是性能的根本。
  • 再后来，又学会了 SOA 布局、缓存行对齐这些技巧，性能又上了一个台阶。每一次提升，都是因为对硬件的理解更深了一层。

所以啊，徒弟，你现在学的这些东西，不是什么"加分项"，而是基本功。一个 C++ 程序员懂不懂性能，从他写的代码一眼就能看出来。

最后送你一句话：写代码的时候，脑子里要有内存的样子。 做到这一点，你就超过了 80% 的同行。
