🏆 化境期 · 设计模式

11 个示例文件、12 种经典设计模式的 C++ 现代实现 · 从入门到精通

📖 模块简介

设计模式是软件设计中常见问题的经典解决方案，是前辈们总结出来的"最佳实践"。 本模块精选了 12 种最常用、最有价值的设计模式（分放在 11 个示例文件中），每一种都提供多种 C++ 实现方式对比， 从经典的 GoF 写法，到现代 C++ 的模板、lambda、function 等新式写法， 让你不仅理解模式的思想，更能写出符合现代 C++ 风格的优雅实现。

学设计模式不是为了在面试时背诵，而是为了面对复杂问题时，能快速找到合适的设计思路。

🗂️ 三大类型模式

🏗️ 创建型模式

处理对象创建机制，根据情况用合适的方式创建对象，增加已有代码的灵活性和可复用性。

🔌 结构型模式

处理类或对象的组合，将不同的类/对象组装成更大的结构，同时保持结构的灵活和高效。

🎭 行为型模式

处理对象之间的通信和职责分配，让对象之间能够高效、灵活地协作完成任务。

📚 学习建议

  • 先理解思想，再看实现：每个模式先搞清楚它解决什么问题、核心思想是什么。代码实现只是思想的载体，理解了思想，你自己也能写出来。
  • 对比不同实现方式：每个模式都有多种写法。对比一下，看看各种写法的优缺点分别是什么，分别适合什么场景。
  • 在真实代码中寻找模式：读完一个模式，去你项目的代码里找找，看看有没有地方已经在用这个模式（不管是有意还是无意的）。在真实场景中识别模式，比死记硬背有用得多。
  • 不要为了用模式而用模式：这是初学者最容易犯的错。手里拿着锤子，看什么都是钉子。设计模式是工具箱，不是万能药。简单的问题就用简单的解法，别搞复杂了。
  • 模式是可以组合的：真实项目中，往往是多个模式组合使用。比如观察者+策略、工厂+模板方法、装饰器+策略……学多了你自然会融会贯通。
  • 现代 C++ 让模式变得不同：很多 GoF 时代的模式，在现代 C++ 中有了更简洁的实现方式（比如用 function/lambda 替代策略模式的继承体系）。保持开放的心态，与时俱进。

👴 老师傅的话

徒弟，设计模式这东西，说重要也重要，说不重要也不重要。

重要在哪？它是一种"共同语言"。你跟另一个程序员说"这里用观察者模式"，对方马上就明白你的设计思路了，不用解释一大堆。这大大降低了沟通成本。

不重要在哪？真正的高手，手里无剑心中有剑。他们不会刻意去想"我要用什么模式"，而是根据问题自然地设计，回头一看，哦，这不就是某某模式嘛。模式已经内化了。

师傅给你几句经验之谈：

  • 别拿模式当教条。 GoF 的 23 种模式是 90 年代总结的，那时候还是 Smalltalk 和 C++ 的天下。这么多年过去了，语言特性变了很多，有些模式已经有了更好的替代方案。学模式学的是思想，不是死记 UML 图。
  • 简单永远是第一位的。 如果一个简单的函数就能解决问题，就别搞什么类、继承、模式。为了用模式而用模式，是最愚蠢的。
  • 模式的名字只是标签。 关键是理解它解决了什么问题、在什么场景下用。你不知道某个模式的名字没关系，只要你知道遇到类似问题该怎么设计就行。
  • 多读好代码。 去看看 STL、Boost、Qt 这些优秀库的源码，你会发现设计模式无处不在，但它们从来不会写着"这里用了 XX 模式"。好的设计是润物细无声的。
  • 重构中学习模式。 先写一个能用的版本，然后回头看：哪里重复了？哪里不够灵活？哪里以后可能要扩展？在重构的过程中，你会自然而然地用到设计模式。

设计模式的最高境界，是忘记所有模式的名字，但写出的代码处处符合模式的思想。慢慢修炼吧。
