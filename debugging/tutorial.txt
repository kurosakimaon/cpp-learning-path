【一、模块简介】

徒弟啊，有人说程序员工资里有一半是写代码的钱，
另一半是调 bug 的钱。话糙理不糙。

写代码谁都会写，调 bug 才见真功夫。
同样一个 bug，新手可能折腾一天还找不到原因，
老手可能十分钟就定位了。这就是差距。

调试这东西，不是天生就会的，是练出来的。
但也有方法和套路。这个模块就给你讲讲
调试的基本思路、常用工具、常见 bug。

学会了这些，你调 bug 的效率能上一个台阶。


【二、学习目标】

学完本模块，你要能做到：

  1. 掌握系统的调试方法（六步调试法）
  2. 会用 printf 调试法定位简单问题
  3. 认识 C/C++ 常见的 bug 类型
  4. 会用 Sanitizers 检测内存错误
  5. 养成开警告、开 Sanitizer 的好习惯


【三、文件列表与学习重点】

咱一共 3 个文件，个个实用：

  01_print_debugging.cpp      ← printf 调试法（基本功）
    重点：怎么打日志、怎么缩小范围、调试宏的写法

  02_common_bugs.cpp          ← 常见 bug 大全
    重点：内存越界、野指针、内存泄漏、未初始化变量、
          类型转换、整数溢出……

  03_sanitizers_demo.cpp      ← Sanitizers 实战（大杀器）
    重点：AddressSanitizer、UndefinedBehaviorSanitizer、
          LeakSanitizer 的使用方法


【四、学习顺序建议】

师傅建议你这么学：

【第一步：先学方法论（六步调试法）】
   不管你用什么工具，思路是一样的。
   先把调试的正确流程搞清楚，
   别上来就瞎试、瞎改代码。

【第二步：printf 调试法（01）】
   有人觉得 printf 调试很 low，师傅不同意。
   printf 调试是基本功，简单粗暴，
   任何环境、任何语言都能用。
   很多老手写了十几年代码，还是习惯用 printf 调。

   关键不是工具，是思路。
   怎么打日志、打在哪、打什么，这才是学问。

【第三步：常见 bug 集锦（02）】
   知己知彼，百战不殆。
   知道常见的 bug 长什么样，
   遇到问题你才能快速反应：
   "哦，这症状像是越界了"、
   "这应该是用了未初始化的变量"。

【第四步：Sanitizers（03）—— 大杀器】
   这是 C/C++ 程序员的福音。
   内存越界、使用已释放内存、未初始化变量、
   内存泄漏、整数溢出……
   以前这些 bug 要查半天，
   有了 Sanitizer，一跑一个准。

   一定要学会用！开发阶段一直开着，
   能帮你揪出好多隐藏的 bug。


【五、核心知识点梳理】

咱把最核心的东西拿出来说说：

1. 【六步调试法】
   第一步：稳定复现
     bug 能稳定复现，就等于解决了一半。
     复现不了？先想办法让它能稳定复现。

   第二步：缩小范围
     用二分法、注释法，一步步缩小问题范围。
     最后定位到某一行、某一个函数。

   第三步：提出假设
     根据现象，推测可能是什么原因导致的。
     别怕假设错，就怕没假设。

   第四步：验证假设
     改代码、加日志、用调试器，
     验证你的假设对不对。
     对了最好，错了就换个假设。

   第五步：修复
     找到原因了，修复就简单了。
     但要注意：别只治症状，要治根。

   第六步：验证修复
     修完了一定要验证！
     原有的 bug 没了，也别引入新的 bug。

2. 【printf 调试的精髓】
   printf 调试不是到处乱打 cout。
   关键是：
   - 打关键变量的值，看是不是预期的
   - 打函数的入口和出口，看有没有走到
   - 用二分法，一半一半地打，快速缩小范围
   - 用好调试宏，可以随时开关

3. 【常见 bug 类型】
   - 段错误（Segmentation Fault）：
     一般是访问了非法内存，野指针、越界、空指针解引用
   - 结果不对：
     逻辑错误、运算符优先级、类型转换、溢出
   - 内存泄漏：
     new 了没 delete、shared_ptr 循环引用
   - 未定义行为：
     未初始化变量、越界访问、有符号整数溢出……

4. 【Sanitizers 三大件】
   - AddressSanitizer（ASan）：
     检测内存错误：越界、使用已释放内存、栈溢出等
     编译加 -fsanitize=address

   - UndefinedBehaviorSanitizer（UBSan）：
     检测未定义行为：整数溢出、空指针解引用等
     编译加 -fsanitize=undefined

   - LeakSanitizer（LSan）：
     检测内存泄漏
     编译加 -fsanitize=leak（ASan 自带）


【六、常见坑与注意事项】

1. 【改代码瞎试】
   新手调 bug 最容易犯的毛病：
   看到 bug 也不想原因，咔咔改代码，
   改完一跑，哎，好了？
   但你知道为什么好吗？不知道。
   下次再遇到类似的，还是不会调。

   调 bug 一定要先想原因，再验证。
   知其然，更要知其所以然。

2. 【忽略编译器警告】
   编译器警告是免费的 bug 检测！
   很多 bug 在编译阶段就警告你了，
   你非要忽略，那怪谁？

   师傅建议：警告全开（-Wall -Wextra），
   警告当错误处理（-Werror）。

3. 【printf 改变了行为】
   加了个 printf，bug 没了？
   别高兴太早。大概率是时序变了，
   或者内存布局变了，bug 藏起来了。
   并发 bug 和内存 bug 经常这样。

4. 【Sanitizer 不是万能的】
   Sanitizer 能检测很多问题，但不是所有问题。
   逻辑错误、算法错误，它检测不出来。
   而且开了 Sanitizer 程序会慢很多，
   性能相关的 bug 可能就复现不了了。

5. 【调试器不会用也没关系】
   很多人觉得不会用 gdb/lldb 就不算会调试。
   其实不是。printf 调试用好了，
   效率不一定比调试器低。
   当然，调试器该学还是要学的，
   但也别神化它。


【七、老师傅的经验之谈】

1. 【开警告、开 Sanitizer，越早越好】
   徒弟，听师傅一句劝：
   从你写第一个 C++ 程序开始，
   就把警告全开，把 Sanitizer 打开。

   这俩东西能帮你在早期就发现大量 bug，
   省得后面花几天几夜去查。
   习惯了之后，你写代码的质量也会越来越高。

2. 【橡皮鸭调试法】
   说出来你可能不信，师傅调 bug 经常自言自语。
   把问题说一遍，说着说着就想通了。

   这就是著名的"橡皮鸭调试法"：
   放个橡皮鸭在旁边，把问题讲给它听。
   讲的过程中，你自己就把思路理清楚了。
   真的管用，不信你试试。

3. 【调 bug 也是一种能力】
   别觉得调 bug 是浪费时间。
   每调一个 bug，你对语言、对系统的理解
   就深一分。调的 bug 多了，
   你写代码的时候就会自然而然地避开坑，
   写出 bug 更少的代码。

   所以别怕 bug，bug 是最好的老师。

4. 【二分法是万能的】
   不知道 bug 在哪？用二分法。
   注释掉一半代码，还复现吗？
   复现就是另一半的问题，
   不复现就是这一半的问题。
   几轮下来就定位了。

   git 里有个 bisect 命令，
   就是用二分法找哪个 commit 引入的 bug。
   神器，有空可以学学。

5. 【写代码的时候就想着怎么调试】
   老手写代码，写的时候就想着：
   这儿容易出问题，加个日志；
   这儿状态复杂，加个断言；
   这儿边界情况多，加个错误处理。

   不是等出了 bug 才想怎么调，
   是写代码的时候就为调试做好准备。
   这才是高手的做法。
