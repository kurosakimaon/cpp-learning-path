# 蜕变期 · STL 与内存

> 从会写代码到写好代码的关键一步

## 一、模块简介

徒弟，恭喜你过了筑基期。到这一关，你已经能写 C++ 代码了，但写得好不好、优不优雅、安不安全，那就是另一回事了。

这个模块叫"蜕变期"，意思就是从"会写"到"写好"的蜕变。核心就两样东西：内存和 STL。

RAII 是 C++ 的灵魂，STL 是 C++ 的兵器库。这俩吃透了，你才算真正入门了现代 C++。

## 二、学习目标

学完本模块，你要能做到：

1. 深刻理解 RAII 思想，知道它为什么是 C++ 的灵魂
2. 熟练使用 STL 常用容器，知道什么时候用哪个
3. 理解 STL 容器的底层原理，不只会调 API
4. 会用智能指针，知道 `shared_ptr` 的陷阱在哪
5. 养成良好的编程习惯，写出规范、安全的代码

## 四、学习顺序建议

师傅给你指条明路：

### 第一步：先啃 RAII（memory_model_raii.cpp）

RAII 是现代 C++ 的基石。智能指针、STL 容器、锁保护……底层全是 RAII。这一节一定要吃透，不然后面学智能指针都是空中楼阁。

什么是 RAII？简单说就是：资源获取即初始化，构造时申请，析构时释放。让对象帮你管资源，不用自己记得释放。

### 第二步：STL 容器（stl_containers.cpp）

别光背 API，要理解底层。

- `vector` 底层是啥？为啥扩容是 1.5 倍或 2 倍？
- `list` 为啥不能随机访问？
- `map` 和 `set` 底层为什么用红黑树？
- `unordered_map` 的哈希表是怎么回事？

理解了底层，你才知道什么时候该用哪个容器。

### 第三步：STL 算法（stl_algorithms.cpp）

算法和容器是靠迭代器连起来的。先搞懂迭代器的分类，再学常用算法。能用 STL 算法就别自己写循环。

### 第四步：智能指针（smart_ptr_deep.cpp）

`unique_ptr` 简单，`shared_ptr` 要小心。重点看循环引用问题和 `weak_ptr` 的解法。自定义删除器也要了解一下。

### 第五步：编程规范（coding_practices.cpp）

规范这东西，新手觉得没用，老手觉得太重要了。为什么 Google、腾讯都有自己的编码规范？因为规范能避免很多低级错误。

## 五、核心知识点梳理

咱把最核心的东西拎出来：

### 1. RAII 到底是什么

资源（内存、文件句柄、锁……）的管理，交给对象的生命周期来负责。构造函数获取资源，析构函数释放资源。这样不管函数怎么 return、怎么抛异常，资源都能正确释放。

这就是 C++ 比 C 安全的根本原因之一。

### 2. STL 容器怎么选

- 需要随机访问、尾部操作多 → `vector`
- 中间插入删除多 → `list`（但一般也不用，用 `vector` 就行）
- 两头插入删除多 → `deque`
- 需要键值对、有序 → `map`
- 需要键值对、查找快 → `unordered_map`
- 去重、有序 → `set`
- 去重、查找快 → `unordered_set`

大部分场景，`vector` 就够了。

### 3. vector 扩容机制

`vector` 底层是连续内存。满了怎么办？找一块更大的内存，把旧数据拷过去，释放旧内存。一般扩 1.5 倍或 2 倍。所以 `push_back` 均摊复杂度是 O(1)。

### 4. shared_ptr 的引用计数

`shared_ptr` 内部有个引用计数，多一个指针指向同一块内存，计数就加一，少一个就减一。计数到 0 就释放内存。听起来很美好，但有个大坑：循环引用。

### 5. weak_ptr 的作用

`weak_ptr` 不增加引用计数，就是个"观察者"。专门用来打破循环引用。用之前要先 `lock()` 一下，看看对象还在不在。

## 六、常见坑与注意事项

### 1. vector 迭代器失效

`push_back` 可能导致扩容，所有迭代器都失效。`insert/erase` 也会导致部分迭代器失效。用范围 for 循环的时候别随便改容器大小。

### 2. map 的 operator[] 陷阱

`map["key"]` 如果 key 不存在，会自动插入一个默认值！只是想查找的话，用 `find()`，别用 `[]`。

### 3. shared_ptr 循环引用

A 指向 B，B 指向 A，循环里的对象互相持有，引用计数不会归零（没有外部引用时通常是 1），谁都释放不了，内存泄漏。解决方法：其中一个用 `weak_ptr`。

### 4. 用裸指针创建 shared_ptr

别这样：`shared_ptr<int> p(new int(5));`  
要用：`auto p = make_shared<int>(5);`  
`make_shared` 更高效，也更安全。

### 5. STL 算法比手写慢？

别想当然。STL 算法都是高手写的，优化到极致了。你手写的不一定比它快。而且 STL 算法更不容易出错。

## 七、老师傅的经验之谈

### 1. RAII 是 C++ 的灵魂，一定要吃透

徒弟，这话师傅放这儿：不理解 RAII，你就永远不算真正懂 C++。RAII 不是什么技巧，是一种思维方式。以后你写任何类，都要想想：这个类管什么资源？构造时获取了吗？析构时释放了吗？拷贝的时候怎么办？移动的时候呢？

### 2. STL 不是黑盒，要理解底层

很多人用 STL 用了好几年，连 `vector` 底层是数组都不知道。这不叫会用，这叫"会调 API"。理解了底层原理，你才能写出高效的代码，才能知道什么时候用什么容器，才能避免各种坑。

### 3. 智能指针不是万能的

有了智能指针，不代表你就不用管内存了。循环引用、自定义删除器、线程安全……坑多着呢。智能指针只是工具，工具用得好不好，还得看人。

### 4. 编程规范为什么重要

新手觉得规范是束缚，老手知道规范是保护。规范是无数前辈踩坑踩出来的经验总结。照着规范写，能避开 80% 的低级错误。从一开始就养成好习惯，受益终身。

### 5. 多看 STL 源码

STL 源码是最好的 C++ 教材。不用全看，挑几个常用的看看：`vector` 的实现、`shared_ptr` 的实现、`sort` 算法的实现……看完你会对 C++ 有全新的认识。

> 蜕变期就到这儿。过了这一关，你写的代码才算是"现代 C++ 代码"。RAII 要刻在脑子里，STL 要用得顺手。后面的路还长，但基础打牢了，走起来就稳了。
